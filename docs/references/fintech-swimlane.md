# Типовой финтех-процесс — swimlane

Источник: `.external/Типовой_процесс_безопасной_разработки_для_финтеха.pdf` (интерпретация схемы).

## Зоны

| Зона | Данные | Примечание |
|------|--------|------------|
| Среда разработки | Синтетические | IDE, лёгкий SAST, линтеры |
| Зона тестирования QA | Синтетические | Unit, fuzzing, sanitizers |
| Зона UAT | Подготовленные тестовые | DAST, IAST, нагрузка |
| Зона эксплуатации | Реальные | WAF, RASP, SBOM monitor |
| Зона управления ИБ | — | Политики, triage, ASTO |

Допускается **окружение на feature branch**.

## Security Gate на MR/PR

Компоненты gate (параллельно):

- **SAST** — лёгкий/первичный в IDE; полный в CI
- **Линтеры** — style + security linters
- **Secret-check** — секреты в коде
- **Лишние файлы** — бинарники, запрещённые типы
- **SCA** — после SBOM на этапе сборки

Два варианта IDE SAST (из схемы):

1. Независимый плагин на ПК разработчика
2. Интеграция с корпоративным SAST (политики с сервера)

## Дизайн и анализ

- **Threat model / поверхность атаки** — параллельно или отдельным процессом
- **Taint Analysis Tool** — уточнение поверхности атаки (SecChamp)
- Привязка к **ГОСТ 56939** этапам 5.6–5.7

## Тестирование (QA / UAT)

| Вид | Артефакты | Инструменты |
|-----|-----------|-------------|
| Unit-тесты | Корпус тестов | Test management |
| Фаззинг | Фаззинг-тесты, seeds | AFL++, Jazzer, go-fuzz |
| Concolic | Исходный код + корпус | спец. движки |
| Sanitizers | Сборки | ASan, Valgrind |
| DAST | Сценарии динамического тестирования | ZAP, Burp |
| Code coverage + DAST | Покрытие + DAST | измерение покрытия |
| Тесты утечек ПДн | Тесты на защищаемую информацию | кастомные |
| Нагрузочное | Генератор нагрузки | k6, JMeter |

## Сборка и артефакты

- Централизованная **шаблонизация конвейеров**
- **SBOM** (SCA) — обязательный артефакт
- **Подписанные артефакты** (опционально на схеме)
- **Размеченный отчёт SAST** — triage SecChamp / Аналитик ИБ

## Эксплуатация

- **ASTO** — агрегированное управление уязвимостями из SAST/DAST/SCA
- **IRM/GRC** — риски и compliance
- **OBOM** + SBOM в мониторинге уязвимостей зависимостей
- **Security Gate на SCA** в CD — «не стало хуже»
- Container scan, **RASP**, **WAF**, **API Sec**, **IAST** (в тестовой зоне)

## Роли (расширенные)

Разработчик, SecChamp, Аналитик ИБ, QA, DevOps, PO, PM, Инженер эксплуатации, Инженер ИБ (контроллер эксплуатации).

## Комментарии на схеме

- Все артефакты по задаче — в трекере
- Trunk-based — основной сценарий
- Допускается принятие риска с отложенными проверками
- **Bugfix:** упрощённый gate, пропуск UAT
